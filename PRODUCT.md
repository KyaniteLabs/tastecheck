# TasteCheck

A frontend direction-and-verification toolkit for coding agents: interview for a design system, improve/deslop an existing UI, then judge the real rendered result with evidence and a fail-closed SHIP/HOLD gate. It is not an autonomous designer or proof that a UI has good taste.

## Existing surfaces

- Verified inventory: 20 Markdown skills, 20 canonical slash commands plus one alias, and eight gallery systems. Skills cover direction, foundations, component states, accessibility, copy and final verification.
- A Node CLI for installation, audit, local taste profiles and calibration, plus a shell installer. Current CLI source/help exposes `audit`, despite README prose saying no published audit CLI; this document describes the checkout, not installed-registry parity.
- CDP browser evidence driver, deterministic contract/release/evaluation machinery, gallery/landing and labeled regression corpora. The inspected driver declares 13 named probes with required/optional status, not merely a screenshot command.
- Gate-integrity and visual-tell corpora, not independent proof of design effectiveness. README reports 17 gate cases and a 36-page visual corpus with their limited scope; those measured rates were not rerun for these docs.

Effectiveness remains BLOCKED. Historical/source-bound release PASS receipts do not transfer automatically to this docs head. Subjective gestalt/brand-fit judgment still needs a named basis and accountable review.
